# MONOLITH · Renovation Hero

## Новый сценарий

На первом экране одна и та же кухня-гостиная проходит пять состояний:

1. Черновое помещение → «Всё начинается с идеи».
2. Чистовой пол и стены → «Пространство обретает форму».
3. Тёплое освещение → «Свет меняет всё».
4. Кухонная мебель и обеденная зона → «Каждая деталь на своём месте».
5. Полностью обставленная кухня-гостиная → «Интерьер, в котором хочется жить» и CTA.

Это концептуальное преображение, а не документальные кадры реально выполненного ремонта.

## Архитектура

- `src/components/HeroTour.tsx` — один ScrollTrigger, регулирующий маски, текст, прогресс, навигацию и CTA. API `HeroTour` сохранён.
- `src/lib/renovation-scenes.ts` — редактируемые названия, заголовки, тексты, пути к WebP и границы этапов (0–1). Источник данных отделён от UI, поэтому в будущем можно подключить CMS/админку.
- `public/images/hero-renovation/` — пять зарегистрированных оптимизированных WebP 1672×941.
- `src/lib/renovation-blur.ts` — миниатюрные заглушки.
- `data/renovation-alignment.json` — проверка регистрации фотографий по общей архитектуре.
- `src/components/Reveal.tsx` — четыре варианта анимации появления блоков (`rise`, `headline`, `card`, `quiet`), stagger через delay, без скрытия контента при отключённом JS.
- `src/components/HomepageMotion.tsx` — тихий параллакс двух больших интерьерных изображений на широких экранах.

### Технология переходов

Все изображения имеют одинаковую геометрию после выравнивания по неподвижным деталям остекления (SIFT + RANSAC, affine registration). НОВЫЙ кадр открывается поверх старого с мягкой границей шириной примерно 16% изображения. Старый кадр целиком остаётся позади, поэтому нет пустых чёрных промежутков. Поверх всего стека применяется одно общее движение камеры, исключающее рассинхронизацию слоёв.

Центры переходов: 0.10–0.28, 0.32–0.50, 0.54–0.70, 0.74–0.90. Последние 10% скролла отведены для финального CTA. Кнопки расположены отдельной grid-строкой ниже зарезервированной области текста.

Первая фотография грузится приоритетно. Остальные монтируются до появления и готовятся до раскрытия маски. При медленном интернете текущий кадр остаётся на экране до загрузки следующего. `next/image` подбирает формат/ширину под устройство. Мобильная версия не использует параллакс. `prefers-reduced-motion` показывает статичную финальную сцену без длинного тура.

## Запуск

1. Распакуйте проект.
2. Для немедленного автономного просмотра откройте `OPEN_RENOVATION_PREVIEW.html` в Chrome/Edge (там отдельная демонстрация Hero, без Next.js).
3. Для полного сайта: `npm install`, затем `npm run dev`, открыть `http://localhost:3000`.
4. Проверить сборку: `npm run typecheck`, `npm run lint`, `npm run build`.

## Границы проверки в данной среде

- TypeScript: пройден.
- ESLint: пройден.
- Next.js production build: не удалось проверить: локальный архив содержал Windows native SWC, а скачать Linux SWC из npm мешает отсутствие сетевого доступа. Требуется проверка на Windows.
- Визуальные скриншоты реального браузера не удалось получить из-за `ERR_BLOCKED_BY_ADMINISTRATOR`; математические координаты и промежуточные маски протестированы отдельно. Автономный HTML включён для самостоятельного осмотра.
- Перед публикацией проверьте на 375/390/768/1440/1920 px, скролл вперёд и назад, скорость сети Slow 4G, обе CTA, reduced motion.

## Функциональность

Портфолио, админ-панель, формы, юридические страницы и их текущий демонстрационный режим не менялись. Коммиты и push не выполнялись.
